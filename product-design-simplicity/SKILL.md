# Product Design Simplicity

## Overview

Use this skill to make product experiences easier to understand, decide in, recover from, and reuse. Treat simplicity as reduced cognitive and operational burden while preserving utility, accessibility, trust, and user agency.

Do not equate simplicity with emptiness, sparse visuals, fewer features at all costs, or hiding necessary controls. Prefer a clearer product over a merely cleaner-looking one.

## Workflow

1. Identify the user, job, context, and primary success path. If these are not provided, state reasonable assumptions before recommending changes.
2. Map the current experience: entry point, primary action, required choices, system state, feedback, errors, and recovery paths.
3. Diagnose complexity using the checklist in `references/review-checklist.md` when doing a review or audit.
4. Apply the principles in `references/principles.md` to choose the smallest changes that reduce burden.
5. Preserve necessary capability: confirm that the simplified design still supports informed choice, reversibility, accessibility, trust, and expert workflows where relevant.
6. Deliver prioritized recommendations with concrete before/after direction. Prefer design actions over abstract advice.

## Simplification Moves

Use these moves in order before inventing new UI:

1. Remove: delete unused, redundant, or low-value elements.
2. Merge: combine duplicate concepts, repeated choices, or adjacent steps.
3. Reorder: put the common path first and advanced or rare paths later.
4. Default: make the safest, most common, or most useful choice automatic while keeping it inspectable.
5. Constrain: prevent invalid choices instead of explaining errors after the fact.
6. Disclose: reveal advanced controls only when the user has intent or context.
7. Clarify: rewrite labels, helper text, empty states, and errors in plain language.
8. Explain: add instructional text only when the interface cannot be made self-evident.

## Output Rules

When reviewing a product or design, lead with the highest-impact changes. For each recommendation, include:

- Problem: what is making the experience harder than necessary.
- Change: the concrete simplification to make.
- Why: the user burden it removes.
- Guardrail: what must remain visible, accessible, reversible, or trustworthy.

When the user asks for a redesign or implementation, make surgical changes that serve the stated goal. Do not add speculative features, extra settings, decorative complexity, or broad redesigns unless the user asks.
